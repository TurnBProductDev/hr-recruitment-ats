{% comment %} One By Job/Role or Source Level row - same shape either way (see dashboard/views.py's _report_metrics), so both tables in reports.html include this instead of duplicating the row/expand markup twice. Each percentage is shown in a .rep-pctval span carrying the full-precision value in data-pct (needed so the %/ratio switch can compute a meaningful ratio even for something under 0.5%, which would otherwise round away to a useless "0%") and its denominator's raw count in data-denom (needed so a genuine 0% can render as "0:N" instead of a nonsensical "1:0") while the visible text itself is rounded to a whole percent - reports.html's JS rewrites that text on toggle. By Job/Role rows only (r.job_codes present - Source Level rows have no such key) additionally get a left "+" that expands to that role's individual job codes, each with its own KPIs - a separate expand block from the existing right "+" (%-of-Applicants), so either can be open independently of the other. Each job code's own raw count is de-emphasised (small/muted, .rep-num-sub) in favour of its %/ratio (.rep-pct-prominent) - the opposite weighting from the role row above it, which is already the bold headline number there. Each column carries both a vs-previous-stage % (.jc-pct-default, shown by default - CSS hides its sibling) and a vs-Applicants-overall % (.jc-pct-vstotal) - reports.html's JS toggles which one is visible in lockstep with the role row's own right "+" (the %-of-Applicants toggle), so opening that also switches the job-code figures to the same "of Applicants overall" framing instead of needing a third toggle. {% endcomment %}
