{% comment %} One By Job/Role or Source Level row - same shape either way (see dashboard/views.py's _report_metrics), so both tables in reports.html include this instead of duplicating the row/expand markup twice. Each stage cell reads "converted /total (pct%)": the big number is the candidates who moved on, the small "/total" is everyone decided at that stage (moved on + rejected there - pending and on-hold candidates left out), and the % is converted / total. See _report_metrics. Each percentage is shown in a .rep-pctval span carrying the full-precision value in data-pct (needed so the %/ratio switch can compute a meaningful ratio even for something under 0.5%, which would otherwise round away to a useless "0%") and its denominator's raw count in data-denom (needed so a genuine 0% can render as "0:N" instead of a nonsensical "1:0") while the visible text itself is rounded to a whole percent - reports.html's JS rewrites that text on toggle. By Job/Role rows only (r.job_codes present - Source Level rows have no such key) additionally get a left "+" that expands to that role's individual job codes, each with its own KPIs - a separate expand block from the right "+" (%-of-Applicants), so either can be open independently. Each job-code column carries both the conversion % (.jc-pct-default, shown by default) and the vs-Applicants-overall % (.jc-pct-vstotal) - reports.html's JS swaps them in lockstep with the role row's right "+". {% endcomment %}
